## Lab 7-1
Analyze the malware found in the file Lab07-01.exe

### Q1
How does this program ensure that it continues running (achieves persistence) when the computer is restarted?

Ans: It creates a service called `MalService` to run every time the system reboots.

![](assets/posts/MA/lab7/7-1pt1.png)


### Q2
Why does this program use a mutex?

Ans: To ensure it is only running one instance of itself at a time. We can see here that it checks if the process is already running by trying to open its mutex. If this works, it terminates itself.

![](assets/posts/MA/lab7/7-1q2.png)


### Q3
What is a good host-based signature to use for detecting this program?

Ans: The mutex `HGL345` and the service `MalService`:

![](assets/posts/MA/lab7/7-1q3pt1.png)


![](assets/posts/MA/lab7/7-1q3pt2.png)

### Q5
What is the purpose of this program?

Ans: To DDOS `http://www.malwareanalysisbook.com`. Firstly, this program runs `` which suggest it is trying to implement a service. 

Secondly, it checks if the mutex `HGL345` has been created by trying to open it. If it successfully accesses the mutex, it will terminate itself to prevent running more than one instances of itself.

![](assets/posts/MA/lab7/7-1q5pt2.png)

If it does not access the mutex, it will proceed to create one.

![](assets/posts/MA/lab7/7-1q5pt3.png)

Thirdly, it will call `OpenSCManagerA` which means it will add or modify a service later on.

![](assets/posts/MA/lab7/7-1q5pt4.png)

Fourthy, it creates the malicious service.

![](assets/posts/MA/lab7/7-1q5pt5.png)

Fifthly, it gets the date 1 Jan 2100 in filetime format

![](assets/posts/MA/lab7/7-1q5pt6.png)


Sixthly, it passes this to `SetWaitableTimer` , which means it will wait till that date

![](assets/posts/MA/lab7/7-1q5pt7.png)

Seventhly, it waits for the timer to activate via `WaitForSingleObject`

![](assets/posts/MA/lab7/7-1q5pt8.png)

When the timer sets off, it creates 20 threads as seen here it creates one thread every time it decrements with it needing to decrement 20 times.

![](assets/posts/MA/lab7/7-1q5pt9.png)

## Lab 7-3
### Analysis of the EXE

Firstly, it creates a file `C:\\Windows\\System32\\Kernel32.dll` and copies the content of `Lab07-03.dll` into it. 

![](assets/posts/MA/lab7/7-3pt1.png)

![](assets/posts/MA/lab7/7-3pt2.png)


Secondly, it now goes to `sub_4011E0`. Im guessing it is searching the `C:` directory based on `C:\\*` being pushed onto the stack right before `sub_4011E0` is called.

![](assets/posts/MA/lab7/7-3pt3.png)

Now it is trying to find a file in the `C:` directory. 

![](assets/posts/MA/lab7/7-3pt4.png)

It is trying to find files with `.exe` in their filename, meaning it is checking through all files in C: if it is an executable

![](assets/posts/MA/lab7/7-3pt5.png)

If it is an executable, `sub_4010A0` is called.

![](assets/posts/MA/lab7/7-3pt6.png)

`sub_4010A0` modifies the file as seen with the calls `CreateFileA`,`CreateFileMappingA` and `MapViewOfFile` being made.

![](assets/posts/MA/lab7/7-3pt7.png)

We can see that it is trying to locate `kernel32.dll` in the executable. When it does locate it, this is ran:

![](assets/posts/MA/lab7/7-3pt8.png)

You don't have to go into every single detail but the main parts to focus on will be `repne scasb` and `rep movsd`. `repne scasb` is to determine the length of the string which is `kernel32.dll` `rep movsd` is to replace the string `kernel32.dll` with `kerne132.dll`. 

`kerne132` is determined as at `rep movsd` it is in `edi`. The value of `edi` moved from `ebx` with `ebx` being `kernel32.dll`.


![](assets/posts/MA/lab7/7-3pt9.png)


After modifying the file, it closes the handle.

![](assets/posts/MA/lab7/7-3pt12.png)

Firstly, this program creates `kerne132.dll` at `System32`. Secondlycopy the malicious DLL file `Lab07-03.exe`'s contents into it. As for why `kerne132.dll` in particular, i am guessing its due to how almost every single executable uses `kernel32.dll` which increases the chances of it being ran. Thirdly, it modifies every executable in `C:` to use `kerne132.dll` instead of `kernel32.dll` which is its method of persistence.

#### EXE
Firstly, this program creates `kerne132.dll` at `System32`. Secondly, it copies the malicious DLL file `Lab07-03.exe`'s contents into it. As for why `kerne132.dll` in particular, i am guessing its due to how almost every single executable uses `kernel32.dll` which increases the chances of it being ran. Thirdly, it modifies every executable in `C:` to use `kerne132.dll` instead of `kernel32.dll` which is its method of persistence.  

#### DLL
Communicate with the attacker's C2 server.

### Q4
How could you remove this malware once it is installed?

Firstly, replace `kerne132.dll` content with `kernel32`'s content. This helps in ensuring applications functions as intended. Afterwards, delete the `Lab07-03.exe` and `Lab-07-03.dll`. 
This is under the assumption that `Lab07-03.exe` only runs once and the attacker has no backup plan in case one of its files such as `kerne132.dll` were deleted or altered.
This does not totally remove the malware as the executable files are still modified but it helps in preventing it properly functioning.
