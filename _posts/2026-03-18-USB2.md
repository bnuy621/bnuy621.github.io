### Step 2

Finding its location and size

#### Go to `root` on the evidence tree:

![root](assets/posts/post20/post20_img4_p2_s1.png)

#### Go to $MFT

The $MFT file contains the meta data for all the files, including where the raw data for them are located.

![MFT](assets/posts/post21/post21_img1_MFT.png)

#### Finding the file entry

As i am looking for `pulchra` i will search `ulchra`:

![search keyword](assets/posts/post21/post21_img2_searchulchra.png)

Results:

![search keyword results](assets/posts/post21/post21_img3_pulch_found.png)


#### Determine if is resident or non-resident:

Find the `$DATA` signature `80 00 00 00`. Afterwards, read offset `0x8`:


![MFT](assets/posts/post21/post21_img4_fileentry.png)


For most files, this value will be `01` which is non-resident. This means the data is stored somewhere else. To get 'directions' to this somewhere else, we need to refer to the cluster chain runs. To know where they are located, go to offset `0x20`:

![location of cluster run chain](assets/posts/post21/post21_img5_clusterrunpointer.png)

A value of `0x40` means it is 64 bytes from the start of `$DATA` :

![cluster run chain](assets/posts/post21/post21_img6_clusterrun.png)

With the value being `31 3A 80 E3 1C`. This can be intepreted in the following way:

```yaml
[location in X bytes after size of file][size in y bytes][y bytes (size in clusters)][x bytes (starting cluster number)]
```

Hence, the starting cluster is `1CE380` (convert to big endian) and the size being `3A`.


### Step 3



#### Go to the filesystem on evidence tree:

![file system on evidence tree](assets/posts/post21/post21_img7_filesystem_ET.png)

#### Go to the starting cluster:

Enter the value of the starting cluster found earlier

Results:

![cluster data](assets/posts/post21/post21_img9_datafound.png)

#### Extracting it

As earlier we found out that it takes up `3A` clusters AKA `58` clusters. As on a NTFS file system there's `8` sectors per clusters with each cluster being `512` bytes. Hence, to find the total size in bytes:

```yaml
(clusters) * (sectors per cluster) * (bytes per cluster)
```

Size of `pulchra.png` in bytes:

![size in bytes](assets/posts/post21/post21_img10_sizebytes.png)


After finding the total size in bytes, set the selection size to be it:

![selection size](assets/posts/post21/post21_img11_selectionlength.png)

Save selection:

![saving it](assets/posts/post21/post21_img12_name.png)

Extracted file will now work:

![result](assets/posts/post21/post21_img13_RESULT.png)
