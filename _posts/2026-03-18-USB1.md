## Introduction
This guide covers how to manually recover deleted data from a USB using the NTFS file system.

## Prequisites
Have FTK imager installed. Have a .E01 image of the USB.


## Steps

### Step 1 - Load the E01 image into FTK imager


#### Add evidence item:

![evidence item](assets/posts/post20/post20_img1_p1_s1.png)

#### Select source:

![source](assets/posts/post20/post20_img2_p1_s2.png)


#### Select source path:

![source path](assets/posts/post20/post20_img3_p1_s3.png)

Click on `finish` after entering the source path of the .E01 file.



### Step 2 - Finding short file name entry


#### Go to `root` on the evidence tree:

![root](assets/posts/post20/post20_img4_p2_s1.png)

Find the short file name entry. Do this by searching for the name of the file. 

![find](assets/posts/post20/post20_img5_p2_s2.png)

![find](assets/posts/post20/post20_img6_p2_s3.png)

Results:

![file found](assets/posts/post20/post20_img7_p2_s4.png)

To verify the file is correct, ensure the long file name is correct too:

![evidence item](assets/posts/post20/post20_img8_p2_s5.png)



### Step 3 - Finding the first cluster entry

#### Find first cluster entry location
Find the first cluster which is located at offset `0x1A` of the short file name entry:

![first cluster value](assets/posts/post20/post20_img9_p3_s1.png)

Afterwards, use this value and mulitply it by 4 as each cluster entry in the FAT file system is 4 bytes. The value i got is `C`

#### Go to FAT1 on the evidence tree:

![FAT1](assets/posts/post20/post20_img10_p3_s2.png)

#### Go to offsset calculated earlier:


![offset](assets/posts/post20/post20_img11_p3_s3.png)

I used `C` as the offset value.

#### Locate the first cluster entry:

![offset](assets/posts/post20/post20_img13_p3_s5.png)

This shows the second cluster entry is `4`, hence the first is `3` (4-1)


### Step 4

#### Go to the `FAT32` file system on the evidence tree:

![offset](assets/posts/post20/post20_img14_p4_s1.png)

#### Go to first cluster entry:

![offset](assets/posts/post20/post20_img15_p4_s2.png)

![offset](assets/posts/post20/post20_img16_p4_s3.png)

![offset](assets/posts/post20/post20_img17_p4_s4.png)

To extract the file , we need to know its size in bytes. 

#### Go to `root`on the evidence tree:

![root](assets/posts/post20/post20_img4_p2_s1.png)

#### Getting its size in bytes

View the properties of the file to get its physical size:

![offset](assets/posts/post20/post20_img18_p4_s5.png)


#### Set selection length

Go back to the first cluster, and set selection length:

![offset](assets/posts/post20/post20_img18_p4_s5.png)

![offset](assets/posts/post20/post20_img19_p4_s6.png)

![offset](assets/posts/post20/post20_img20_p4_s7.png)

Now the bytes are highlighted:

![offset](assets/posts/post20/post20_img21_p4_s8.png)

#### Extracting the file

Save selection:

![offset](assets/posts/post20/post20_img22_p4_s9.png)

I will name it as `recovered.png`:

![offset](assets/posts/post20/post20_img23_recovered.png)
